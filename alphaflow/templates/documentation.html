AlphaFlow Developer Handbook

Overview

AlphaFlow is a standalone Flask application that scans one past trading day of OPRA option trades for aggressive call buying in small and mid caps ("sweeps"). It is separate from the Market Terminal (options_whale) and runs on port 5001. Its only link to the main pipeline is that the daily email appends the top results from alphaflow.db when that file exists.

System Architecture

  • Frontend (templates/index.html): A visual node-based canvas built in Vanilla JS using Drawflow (pinned to version 0.0.60 on jsDelivr). It shows the stored results when the page loads.
  • Backend Server (server.py): A small Flask server: GET /, GET /documentation, POST /api/scan (JSON config: scan_date, min_spend, vol_oi) and GET /api/results. It listens on 0.0.0.0:5001 with no authentication; ALPHAFLOW_DEBUG=1 turns on the Flask debugger and limits it to 127.0.0.1.
  • Execution Engine (engine.py): Runs the scan against Databento and yfinance and writes results to SQLite.
  • Universe cache (cache_universe.py → small_caps.csv): Filters a fixed seed list of tickers to a $100M–$10B market cap via yfinance.
  • Database (alphaflow.db): Local SQLite file with the swing_plays table (not committed).

1. The Execution Engine (engine.py)

The engine scans the date given as scan_date (default: yesterday). When the Databento query succeeds, it replaces the stored results with what it finds. When the query cannot run, it keeps the stored results and reports why.

Universe Pre-Filter

An OPRA query across every listed ticker is expensive, so the scan only covers the tickers in small_caps.csv. Build that file with python alphaflow/cache_universe.py; it checks a fixed seed list against a $100M–$10B market-cap range. If the file is missing, get_cached_universe() falls back to three demo tickers.

The Databento Query

The engine reads DATABENTO_API_KEY (or its alias DB_API_KEY) through the project's config.py, which loads the project's .env, and queries the OPRA tcbbo schema with parent symbology (<TICKER>.OPT). With no key, or on an API error, the scan stops with an error message and the stored results stay as they were. A query that works but finds no trades (a holiday, for example) stores an empty result.

client = db.Historical(key=config.DATABENTO_API_KEY)
client.timeseries.get_range(
    dataset='OPRA.PILLAR',
    schema='tcbbo',
    symbols=[f"{sym}.OPT" for sym in symbols],
    stype_in='parent',
    start=date,
    end=f"{date}T23:59:00"
)

Detection

  • Keep call trades at or above the ask (when the ask is present).
  • Sum each contract's trades into 15-minute windows.
  • A window is a sweep when premium ≥ min_spend (default $50,000), volume ≥ 100, and volume ÷ open interest ≥ vol_oi (default 1.5). Open interest is fetched from yfinance only for windows that pass the first two tests.
Fixed placeholders: the stored expiration is always the scan date plus 44 days, term is always "Mid Term", entry is always "NEXT OPEN" and max_risk is always 500. They are not computed from the trade.
Results persist across restarts: init_db() only creates swing_plays when it is missing, so saved results survive a server restart. A completed scan replaces the previous scan's rows; earlier scans are not kept.

2. Modifying the Visual Canvas (index.html)

The UI is completely free of React and Webpack. It uses standard DOM manipulation alongside the Drawflow library.

To add a new visual Node, define the raw HTML string inside a backtick template literal, and register it with the editor:

const customNodeHTML = `
<div>
    <div class="title-box"><span>New Filter</span></div>
    <div class="box">
        <label>Parameter</label>
        <input type="text" id="custom_param">
    </div>
</div>`;
editor.addNode('custom', 1, 1, 100, 200, 'custom', {}, customNodeHTML);

3. Database Schema (SQLite)

init_db() in engine.py defines the swing_plays table with CREATE TABLE IF NOT EXISTS. The table is never dropped, so adding a column means changing init_db(), the INSERT in run_historical_scan() and also running an ALTER TABLE swing_plays ADD COLUMN ... on an existing alphaflow.db.

  • id: Auto-increment primary key.
  • date: The scanned trading day.
  • time_of_sweep: Start of the 15-minute window.
  • ticker: Underlying symbol.
  • contract: OPRA option symbol.
  • volume, oi: Window volume and the contract's open interest.
  • spend: Window premium in dollars.
  • term, expiration, entry, max_risk: Fixed placeholders (see above).
